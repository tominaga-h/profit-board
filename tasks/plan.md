## 概要

Nuxt 3 (SPAモード) + Tailwind CSS + Supabase (PostgreSQL / Auth / RLS) + Chart.js で、
SI会社のプロジェクト別営業成績（売上・費用・粗利）を月次管理するMVPを構築する。
基盤（スキャフォールド → DB/RLS → 認証）→ 共通計算ロジック → マスタ編集 → 実績入力 → 集計画面（一覧・ダッシュボード）→ デプロイ、の順に縦切りで積み上げる。

## アーキテクチャ上の決定

- **SPAモード**（`ssr: false`）。SupabaseへはクライアントからAnon Key + RLSで直接アクセス。サーバーAPI層は設けない（SPEC 2章の構成通り）。
- **DBスキーマは SPEC 5.1 のDDLをそのまま採用**（カラム追加・変更なし）。
- **RLSの再帰回避**: 「`m_users` に存在するメールのみ許可」ポリシーを `m_users` 自身にかけると再帰するため、`SECURITY DEFINER` のヘルパー関数 `is_app_user()` を作り全テーブルのポリシーから参照する。
- **計算ロジックは純粋関数のcomposableに集約**（`lib/calc` / `lib/statusJudge` / `lib/fiscalYear`）。稼働人日・金額・粗利率・ステータス判定・年度⇔暦月変換（7月始まり: month 1〜6 は翌暦年）をUIから分離し、Vitestで単体テストする。
- **保存はdelete→insert方式**: 実績入力の保存は対象（年度×月×プロジェクト）の `t_sales`/`t_costs` を削除して再挿入、`t_status` はupsert。行の増減管理をシンプルに保つ。
- **グラフは `<ClientOnly>` + Chart.js（vue-chartjs）**。SPAだが初期化タイミング問題を避ける。
- **マイグレーションはSQLファイルで管理**（`supabase/migrations/`）。Supabase SQL Editorに貼れる自己完結SQLとする。

## 依存関係グラフ

```
T1 スキャフォールド
 ├─ T2 DBスキーマ+RLS+シード
 │    └─ T3 Google OAuth認証+ルートガード
 │         ├─ T5 メンバー一覧 ── T6 メンバー編集 ─┐
 │         ├─ T7 プロジェクト編集 ────────────────┤
 │         │                                      ├─ T8→T9→T10 実績入力
 │         │                                      │        └─ T11 プロジェクト一覧
 │         │                                      │        └─ T12 ダッシュボード集計+KPI
 │         │                                      │             ├─ T13 月次推移グラフ
 │         │                                      │             └─ T14 月次マトリクス
 └─ T4 計算ロジックcomposable（T2/T3と並行可）
                                        T15 仕上げ → T16 デプロイ
```

**並行可能**: T4はT2/T3と並行可。T5〜T7は相互に並行可。T13とT14は並行可。

## リスクと対策

| リスク | 影響 | 対策 |
| --- | --- | --- |
| RLSポリシーの再帰（`m_users` 参照ポリシーを `m_users` 自身に適用） | 高 | `SECURITY DEFINER` 関数 `is_app_user()` を経由（T2で最初に検証） |
| Google OAuth設定ミス（リダイレクトURL、ドメイン検証） | 中 | T3をフェーズ1に置き早期に潰す。localhost/本番両方のURLを最初から登録 |
| 前年同期比・年度またぎ（1〜3月）の集計バグ | 中 | 年度ロジックをT4で純粋関数化しテストで固める。UIは関数を呼ぶだけにする |
| マトリクス表（4行×12ヶ月×N件）の描画性能 | 低 | MVPは全件描画。件数増で問題が出たら仮想スクロール検討（今はやらない） |
